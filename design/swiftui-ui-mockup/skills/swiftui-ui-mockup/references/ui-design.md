# SwiftUIモックのUI設計

## 1. 画面の役割を一文にする

「誰が、何を判断または完了する画面か」を一文にする。複数の目的が並ぶ場合は、主目的を一つ選び、残りを補助情報か次画面へ移す。

## 2. 情報階層を決める

次の順で配置を考える。

1. 現在地と状態
2. 判断に必要な情報
3. 主要アクション
4. 補助アクション
5. 詳細、説明、危険操作

主要アクションを色・位置・サイズのすべてで過剰に強調しない。最も重要な一つだけを明確にする。

## 3. iOS標準パターンから選ぶ

- 階層移動: `NavigationStack`
- 同格の主要領域: `TabView`
- 一時的な作成・編集: `.sheet`
- 破壊的確認: `confirmationDialog` または `alert`
- 選択肢が少ない: `Picker` / `Menu`
- 設定・情報一覧: `Form` / `List`
- 空状態: `ContentUnavailableView`

独自UIは、標準パターンでは目的を達成できない理由がある場合に使う。

## 4. 比較案を作る

案ごとの差は一つの判断軸にする。

良い例:

- A: インライン編集 / B: sheet編集
- A: カード一覧 / B: 時系列一覧
- A: 下部固定CTA / B: ナビゲーションバーCTA

悪い例:

- AとBで配色、情報量、ナビゲーション、文言をすべて変える

各案に「向いている状況」「弱点」「採用を判断する操作」を設定する。

## 5. 状態を設計する

最低限:

- 通常
- 空
- 長文またはデータ量が多い
- 無効・エラー・権限不足のうち該当するもの

入力がある場合は、未入力、入力中、確定後も確認する。

## 6. 文言を具体化する

実際の利用場面が想像できる名詞と数値を使う。ボタンは結果が分かる動詞にする。

- 悪い: 「OK」「項目1」「サンプル」
- 良い: 「リマインダーを追加」「牛乳を冷蔵庫から持っていく」「18:30」

## 7. 視覚チェック

- 8pt前後の一貫した余白リズム
- 本文と補助文の明確なコントラスト
- 主要タップ領域44pt以上
- Dynamic Typeで意味が失われない
- 色だけに状態を依存させない
- Dark Modeでも階層が分かる
